# Phase 5C analyst boundary

`evaluateWithPhase5LLM` accepts an issued Phase 5 analytics snapshot, an explicit evaluation time and expiry, validated model settings, the existing Phase 5B strategy configuration, and an injected completion transport. It sends a bounded precomputed summary to the primary analyst. Directional primary results at or above the configured confidence threshold go to the verifier. Verifier rejection or failure ends in HOLD. The model never supplies contract identity, expiry, quantity, account, or execution authority.

The service captures the issued snapshot and copies caller-owned configuration and collections before awaiting the model. Primary and verifier JSON responses reject duplicate object member names before ordinary parsing. KITE_REAL snapshots carry private, issued freshness proof from real analytics assembly; an injected trusted clock checks that proof before the primary call and again before a candidate returns. These checks use stored timestamps and do not fetch broker data. MOCK replay has no wall-clock freshness requirement.

The final directional proposal always passes through `evaluateStrategy`. Its market quality, exact instrument, spread economics, and confidence gates remain authoritative. The result contains immutable decision evidence, including a canonical SHA-256 digest of the issued analytics, model and prompt versions, concise model rationale, verifier state, and the deterministic strategy result. No decision evidence is persisted in Phase 5C.

`phase5OpenAITransport` reuses the existing lazy OpenAI client and deployed model configuration. Callers must inject it explicitly; tests inject fake responses. `phase5LegacyCompatibleConfig` retains the configured `gpt-4o-mini` baseline. The new prompts and parser are intentionally separate from legacy `callPrimaryAnalyst` and `callVerifier`: legacy verifier failures currently trust the primary, while Phase 5C requires a HOLD when its verifier fails.

The digest covers decision-relevant snapshot values, including spot and timestamps, indicator output and range, qualified option identity, quote economics, Greeks, data mode, and master fingerprints. It is a reference for later durable decision auditing, not a submission key or authorization. Phase 5D may reuse the MOCK path for offline replay. Phase 6 must independently check current readiness, risk admission, and broker mode before any execution.
