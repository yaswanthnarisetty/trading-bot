# Phase 5A/B read-only analytics boundary

`KiteIndexDataService` qualifies NSE `INDICES`/`NSE-INDICES` rows for NIFTY, BANKNIFTY and FINNIFTY by exact Kite CSV `exchange`, `segment`, `instrument_type`, `tradingsymbol`, `name`, non-executable lot/strike/tick fields and broker token. The resulting `KITE:NSE:INDEX:*` identity has `REFERENCE_ONLY` authority. It is separate from Phase 4A `NFO-OPT` qualification and cannot enter an option leg. Missing or ambiguous rows leave that underlying unavailable. The runtime exposes authenticated, request-only index master refresh, quote and historical routes; it has no order methods, timer or fallback.

Kite documents the daily CSV instrument dump, exchange-prefixed quote keys, packet timestamps, absent quote keys and token reuse in [market quotes and instruments](https://kite.trade/docs/connect/v3/market-quotes/). Kite documents token-based [historical candles](https://kite.trade/docs/connect/v3/historical/). Kite staff identify the three NSE index symbols and `INDICES` segment in [index instrument guidance](https://kite.trade/forum/discussion/2825/how-to-get-ticks-for-indices-like-banknifty-nifty-50) and [financial service index guidance](https://kite.trade/forum/discussion/4299/nifty-financial-service-index-is-missing-from-instrument-list-dump). Broker tokens are read from each qualified CSV snapshot, never constants.

`buildRealMarketAnalytics` requires service-issued, current index quote/history and NFO option quotes from the same CSV fingerprint. The spot and quote packets must be fresh; option last trades and the latest finalized index candle must also be recent. Copies and mock values cannot qualify. Missing timestamps, stale master objects, missing exact option quotes, insufficient candles or invalid economics return an unavailable reason. `buildMockMarketAnalytics` is an explicit separate replay/test constructor and retains `MOCK` provenance.

`computeValidatedIndicators` validates 50 or more ordered finalized integer-paise candles before reusing `IndicatorService.computeAll`. `computeQualifiedGreeks` reuses the pure Black-Scholes helpers after Phase 4A qualification; exact expiry date and an explicit `NSE_CLOSE_1530_V1` 15:30 IST close assumption are required. This assumption is deliberately narrow: exceptional exchange sessions need separately verified support. The rate and rate version are explicit inputs, and IV failure is unavailable rather than a guessed Greek.

`evaluateStrategy` accepts a minted analytics snapshot, directional proposal and account-independent quality config. It is deterministic for fixed input, performs no I/O, and returns `HOLD` with a stable reason or an immutable `TradeCandidate` with `executionAuthority: NONE`. Bull put and bear call short/hedge legs are looked up by exact qualified Phase 4A identities. Credit and maximum loss are integer paise using broker-provided lot units. It does not reserve capacity, admit financial risk, call an LLM, or create an order/position/fill.

Phase 5C can supply a directional proposal without changing the evaluator. Phase 5D can construct explicit historical/mock snapshots for replay without using legacy generated contracts. Phase 6 must independently check current execution readiness, RiskAdmission, broker mode, reconciliation and durable order orchestration; a `TradeCandidate` is never authorization to submit.
